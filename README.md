# Task Scheduler

Backend control-plane + operator console for the workloads that the projects generated by [ReactAIClientConfiguration](../ReactAIClientConfiguration) cannot serve inline within an HTTP request — bulk import/update/delete/export, scheduled actions, recurring system jobs.

See [docs/architecture.md](docs/architecture.md) for the canonical design.

## Quickstart (Docker)

Requires Docker Desktop / Docker Engine 24+.

```bash
# 1. Configure secrets
cp .env.example .env
# Replace each REPLACE_WITH_openssl_rand_hex_32 with a real value:
#   openssl rand -hex 32

# 2. Build + start everything (postgres, migrate one-shot, api, web)
docker compose up -d --build

# 3. Create the first operator account
docker compose exec api node dist/scripts/bootstrap-admin.js \
  --email you@example.com --password yourpass --name "Your Name"

# 4. Open the operator console
#    http://localhost:1107
```

Stack components:

| Service | Image | Host port | Notes |
| ------- | ----- | --------- | ----- |
| `postgres` | `postgres:17-alpine` | `5434` (configurable via `POSTGRES_PORT`) | Isolated to this stack via a named volume. |
| `migrate` | `task-scheduler-api` | — | One-shot. Runs `prisma migrate deploy` then exits 0. |
| `api` | `task-scheduler-api` | `4100` | HTTP API + scheduler tick + reaper + in-process worker. |
| `web` | `task-scheduler-web` | `1107` | Nginx serving the SPA, proxies `/api` to `api:4100`. |

Tear down + wipe DB and artifacts:

```bash
docker compose down -v
```

## Local development (no Docker)

Run Postgres however you like (containerized, local install, etc.) and point `SCHEDULER_DATABASE_URL` at it.

```bash
npm install

# Copy + fill in apps/api/.env.example -> apps/api/.env (or export the vars)
cp apps/api/.env.example apps/api/.env

# Apply migrations
npm run prisma:migrate:deploy --workspace=@task-scheduler/api

# Create the first admin
npm run bootstrap-admin --workspace=@task-scheduler/api -- \
  --email you@example.com --password yourpass --name "Your Name"

# Terminal A: API (http://localhost:4100)
npm run dev --workspace=@task-scheduler/api

# Terminal B: SPA (http://localhost:1107, proxies /api to 4100)
npm run dev --workspace=@task-scheduler/web
```

## API surface (summary)

- Auth: `POST /api/admin/auth/login`, `/refresh`, `/logout`, `GET /me`
- Admin CRUD: `/api/admin/users`, `/api/platforms`
- Queue: `/api/jobs` (create, list, get, cancel, artifacts), `/api/schedules` (cron CRUD), `/api/workers`
- Artifacts: `GET /api/artifacts/:id/signed-url` → `GET /api/artifacts/:id/download?e=…&s=…` (signed-URL-authed; no admin auth required for the download itself)
- Dispatch (for future external workers): `/api/dispatch/register`, `/api/dispatch/claim` (long-poll), `/api/dispatch/heartbeat/:jobId`, `/api/dispatch/complete/:jobId`

Two auth surfaces work on the same admin routes:
- Operator JWT issued by the UI login flow
- Static bearer `SCHEDULER_ADMIN_API_KEY` for service scripts and CLI

## Phase-1 scope

Implemented in the control-plane container:

- Queue (claim with `FOR UPDATE SKIP LOCKED`, heartbeat, complete, reaper, retry with exponential backoff, dead-letter)
- Scheduler (cron-driven enqueue with OverlapPolicy: SKIP / QUEUE / CANCEL_PREV)
- Runners: `SYSTEM_CLEANUP_JOBS` (own DB), `SYSTEM_CLEANUP_TOKENS|AUDIT|UPLOADS` (project DB via `PlatformDriver`), `SCHEDULED_ACTION` (project backend via `PlatformDriver`)
- In-process worker loop (per-process concurrency configurable)
- Operator console (CRUD for platforms, jobs, schedules, admins; read-only workers; artifact downloads)

Deferred to Phase 2 (designed but not built in this repo):

- The per-project worker process emitted by the platform generator (`BULK_IMPORT|UPDATE|DELETE|EXPORT` runners live in that worker)
- Platform-repo additions (`taskScheduler` config block, scheduler-worker generator, enqueue-proxy controllers, compose service additions)
